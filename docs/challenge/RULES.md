# Правила и замер (выжимка вкладки Rules & harness)

## Что замеряется
- Рейтинг — медиана по 3 сидам времени **одного вызова**, считающего все 128 произведений (не делится на 128). Сиды выбираются на каждый прогон; перед замером — неучитываемый warm-up.
- С 13.11: копирования можно вынести в `fherma_h2d` / `fherma_d2h`; тогда в рейтинг идёт только `fherma_run` (данные уже на GPU → результат на GPU).
  - `fherma_h2d` — только побайтовое копирование a, b в буферы из `fherma_init`; `fherma_d2h` — только побайтовое копирование результата.
  - В них нельзя запускать ядра, считать, менять раскладку/представление (никаких NTT, RNS, Montgomery, переупаковки, перестановок).
  - `fherma_run` возвращается только после завершения всей своей работы на GPU (cudaStreamSynchronize).
  - Лимиты на кейс: h2d ≤ 0.45 с, d2h ≤ 0.25 с (с 15.11); превышение — нет результата.
  - Нарушение — дисквалификация; FHERMA может проверить исходники.
- `fherma_init` получает только (N, W, L, q), не замеряется, не может зависеть от a и b.

## Требования к реализации
- Полная спецификация на всей допустимой области; N, W, L, q — параметры, а не константы.
- Без внешней сети, всё нужное — в сборке. Проверка может идти и на непубличных входах.
- Специализация под точку и железо разрешена.

## Запрещено (в т.ч.)
- Зашивать/предвычислять ответы, распознавать тестовые входы, лезть к данным верификатора.
- Вмешиваться в харнесс, верификатор, чужие сабмиты, инфраструктуру.
- Любые вычисления в h2d/d2h или возврат из run до окончания работы GPU.
- **Несколько аккаунтов или личностей** для обхода правил.

## Прочее

- Учитывается лучший валидный результат участника.
- Приз выплачивается после финальной проверки (повторный прогон, ревью, KYC).
